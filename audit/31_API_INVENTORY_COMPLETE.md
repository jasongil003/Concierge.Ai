## Shared validation and rate limits

- Admin API mutation requests require `X-CSRF-Token`; admin sessions are server-side, expire, and can be revoked. Every admin API request is capped at 300 per session per minute.
- Guest chat: 20 requests/session/minute. Session start: 240 per source IP per five minutes and 10 per `(IP, client_id)` per five minutes. Resume: 30 per session per minute.
- Most request bodies use bounded Pydantic fields; several domain editors accept generic JSON dictionaries and rely on store-level validation.
- Password-reset request returns a generic message and is capped at 12 requests/direct-peer/hour and 3 requests/hashed-account/hour. Confirmation is capped at 30 requests/direct-peer/hour and 10 requests/hashed-token/hour. Tokens travel in URL fragments and the login page removes them from browser history; verify rate-limit identity behind the production reverse proxy.
- Guest CIDR checks are server-side. `X-Forwarded-For` is used only when the TCP peer matches configured trusted proxy ranges.
