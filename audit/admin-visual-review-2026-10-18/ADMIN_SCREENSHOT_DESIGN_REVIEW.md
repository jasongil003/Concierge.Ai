# Admin Screenshot Design Review

**Review date:** 2026-10-18  ·  **Scope:** Admin portal only  ·  **Environment:** isolated Playwright server at `127.0.0.1:8092` with a temporary synthetic database

## Executive summary

- Reviewed all **210 native baseline PNGs**: 42 Admin destinations at 1920×1080, 1440×900, 768×1024, 390×844, and 375×812. The archive contains 42 desktop/tablet/mobile route groups and is preserved under `before/`.
- Captured **210 after PNGs** at the same five viewport sizes. Each after route waits for the page-specific async data that appeared as a loading placeholder in the first pass. The final 375px rerun also confirms the sidebar edge in the baseline was a transition capture artifact.
- Confirmed visual defects: **P0 0 · P1 0 · P2 2 · P3 0**. Both P2 issues were corrected in scoped Admin CSS and have targeted Playwright assertions.
- Interaction follow-ups for the narrow user/audit tables and personalization tabs passed: hidden columns are horizontally reachable, and the clipped tab can be selected. Static screenshots alone do not establish behavior; these controls received explicit checks.
- The after run uses a fresh, empty synthetic property. Some counts and runtime telemetry therefore differ from the supplied archive. The two layout comparisons assess the affected geometry; values such as CPU utilization and fixture record counts are not pixel-matched.
- A screenshot-matrix retry was needed after disk exhaustion interrupted the 375px test-runner artifact setup. The isolated 375px rerun passed; there was no UI assertion failure. Details are recorded below.

## Confirmed visual defects and fixes

### 1. Appearance builder canvas and inspector — P2, fixed

At 768×1024, the old tablet rule left the three builder columns in place. The library occupied about 260px, the live canvas collapsed to a thin strip, and the inspector was clipped from the viewport. The scoped `#appearance` tablet rule now keeps the library and canvas side by side and moves the inspector below them at full width. The regression test checks minimum canvas/inspector widths and viewport bounds.

Before: [768×1024 PNG](before/screenshots/admin/tablet/admin-appearance-768x1024.png) · After: [768×1024 PNG](after/screenshots/admin/tablet/admin-appearance-768x1024.png) · [test](../../tests/e2e/admin.spec.js#L1034)

### 2. Overview actions at tablet width — P2, fixed

At 768×1024, the timeframe, Refresh data, and Ask AI controls shared the heading row and extended past the viewport. Below 900px the heading now stacks, and its action group uses the available width and wraps. The regression test asserts action bounds, vertical placement, and visibility.

Before: [768×1024 PNG](before/screenshots/admin/tablet/admin-overview-768x1024.png) · After: [768×1024 PNG](after/screenshots/admin/tablet/admin-overview-768x1024.png) · [test](../../tests/e2e/admin.spec.js#L1050)

No global Admin or Guest rules were changed. Both fixes are isolated to the affected Admin regions.

## Design-system review

- The Admin shell uses a consistent navy navigation surface, warm neutral content background, restrained card borders, repeated page-title hierarchy, and semantic status colors. The reviewed screens did not support a cross-page rewrite or global token change.
- Main layout patterns remain recognizable across the five widths: multi-column dashboards and editors at desktop, reduced navigation at tablet, and vertically stacked content at phone widths. The confirmed failures were two local tablet breakpoints, so fixes stay local.
- Tables use horizontal scroll regions where their minimum column width exceeds a phone viewport. The 375px check moved the user and audit table scrollports to the last column and verified that column was visible. The personalization tablist similarly scrolls the requested tab into view and changes the active panel.
- Empty/low-data states are generally explicit, including no active alerts, no knowledge, no map revision, no WLAN observation, and no conversation records. Those values are expected for the fresh E2E property; they are not classified as design defects.
- The initial screenshots contained transient loading states on Conversations, Knowledge, Location, Requests, Personalization Settings, and System Health. The capture helper now waits for each page’s completion signal before saving. This changes test timing only.
- The source 375px Guest screenshot’s 7px sidebar-colored strip disappeared in the after capture after the helper waited for the drawer transform to finish. It was a capture race, not a product defect.
