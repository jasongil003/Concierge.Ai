## MEDIUM

### Cross-property guest hostname ownership — fixed

- **Page/component and role:** Property setup, Network Access, direct guardrail update, and Admin AI configuration; a caller with the applicable property/network-management permission.
- **Reproduction before fix:** Assign a normalized hostname/IP to one property, then attempt to save it as another property’s domain or Guest Access Host, using each domain/host combination and the direct property store path.
- **Expected:** Every second owner is rejected with HTTP 409 and a safe message; the rejected save leaves existing configuration intact.
- **Actual before fix:** Route-specific checks did not cover every writer, so direct/internal updates could bypass ownership checks.
- **Root cause:** Ownership checks were split across routes instead of being enforced at the shared persistence boundary.
- **Files/fix:** app/guardrails.py now owns normalization and the shared validator; app/properties.py checks all upserts inside a serialized transaction; app/main.py maps the conflict to HTTP 409. SQLite writers use an immediate transaction; PostgreSQL writers use a transaction-scoped advisory lock.
- **Regression/status:** tests/test_properties.py, tests/test_network_access.py, tests/test_admin_configuration_actions.py, and the PostgreSQL integration test cover case folding, trailing dots, IDNA/IP canonicalization, duplicates, cross-field collisions, concurrent claims, direct API/AI paths, and unchanged stored configuration after rejection. Passed.

### Malformed guest configuration isolation — fixed

- **Page/component and role:** Host resolution and guest-origin middleware; guest requests across properties.
- **Reproduction before fix:** Persist malformed guest-host configuration for Property B while Properties A and C have valid mappings; request each property’s host and attempt a guest mutation for B.
- **Expected:** A and C remain usable; B fails closed, is logged/audited, and does not erase other properties’ mappings.
- **Actual before fix:** A malformed stored record could abort a global mapping pass and discard valid mappings for neighboring properties.
- **Root cause:** A single parse exception was handled around the entire property enumeration rather than independently per property.
- **Files/fix:** app/guardrails.py extracts valid normalized mappings per record; app/properties.py safely decodes malformed rows and marks bad guest configuration; app/main.py denies guest access only for the affected property and audits it.
- **Regression/status:** tests/test_guardrails.py uses three properties, corrupts B’s stored configuration, verifies A/C return successfully and B is denied. Passed.

## LOW

### Host-conflict error was hidden by a generic UI message — fixed

- **Page/role:** Admin → Network Access; authorized administrator.
- **Reproduction before fix:** Save a hostname already assigned to another property.
- **Expected/actual:** The safe conflict explanation should be shown; the UI instead displayed “Request failed.”
- **Root cause/fix:** The shared fetch helper did not read message fields in structured error details. app/static/admin.js now displays the safe server message.
- **Regression/status:** tests/e2e/admin.spec.js verifies the conflict toast and unchanged saved data after reload. Passed.

### Design page horizontal overflow — fixed

- **Page/role:** Admin → Appearance / Design; signed-in administrator at 1024×768.
- **Expected/actual:** No horizontal overflow; the previous top bar extended 17 pixels beyond the viewport.
- **Root cause/fix:** Duplicate top-bar actions competed with the editor controls. app/static/admin.css hides the duplicate tablet-width actions while editor footer actions remain available.
- **Regression/status:** tests/e2e/manual-qa-responsive.spec.js checks all admin destinations and guest views across eight sizes. Passed.
