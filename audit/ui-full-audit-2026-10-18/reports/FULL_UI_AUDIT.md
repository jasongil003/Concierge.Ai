# Concierge.Ai Full UI Audit

- **Audit date:** 18 October 2026
- **Repository branch:** `codex/ui-full-audit-2026-10-18`
- **Application:** Concierge.Ai
- **Evidence:** [HTML dashboard](UI_AUDIT_DASHBOARD.html) · [full per-control inventory (CSV)](ui-interaction-inventory.csv) · [per-control inventory (JSON)](ui-interaction-inventory.json) · [Playwright census output](interaction-inventory.json)

## Executive summary

The audit discovered **42 Admin destinations** and **5 Guest views**. Playwright navigated each destination and view at all five requested sizes and saved **235 route screenshots**. Two after-fix screenshots and one deterministic before-fix reproduction show the Location editor on desktop and mobile, for **238 screenshots** in the gallery.

The 1440×900 control census recorded **2,162 visible control instances** across the 47 views. This is an instance count across page snapshots, not a count of unique component definitions. **2,111** controls could receive keyboard focus; zero enabled controls were outside keyboard reach, zero controls lacked an accessible name, and zero invalid composite-widget entry points were reported. The census found **5 `role=tab` controls across 2 tablists** (Components, Layers 6, Overview, Privacy & memory, Sources & integrations). The application primarily uses navigation destinations rather than ARIA tabs.

The final full Playwright run completed with **395 passed, 43 skipped, and 0 failed** across desktop Chromium and mobile Chromium. A focused Location workflow rerun with screenshot capture passed in both profiles. The Python suite (excluding five installer tests that refuse to run while the installed app owns port 8080) reported **1,463 passed, 22 skipped, and 5 deselected**.

Two UI issues were fixed: the Guest Sessions refresh button now has a contextual accessible name, and the Location editor focuses its name field synchronously when the dialog opens, avoiding a deferred-focus race. Several stale E2E selectors/fixtures and the platform-specific guest-home visual baselines were updated to match current behavior.

**Coverage limit:** the 2,162 controls were inventoried, named, and checked for focusability, but the inventory did not individually activate every control. Named Playwright workflows verify many high-value actions and journeys; the report does not treat the other controls as PASS. The requested exhaustive per-control click audit is therefore **not complete**. See [Outstanding work](#outstanding-work).

## A. Scope, environment, and safety

- Read-only checks against the already-running local app on `127.0.0.1:8080` returned `/` 200, `/admin` 303 (login redirect), and `/health` 200.
- State-changing UI workflows ran only against the repository Playwright server on `127.0.0.1:8092`, using isolated test data and temporary properties. The live app's persistent database was not used for mutations; its pre/post safety hash was unchanged.
- Responsive screenshots cover **1920×1080, 1440×900, 768×1024, 390×844, and 375×812**. The responsive test checked for horizontal overflow and collected console/page errors and failed/404/5xx requests; all five viewport runs passed.
- The 235 route images are full-page initial-state captures. Two additional Location editor images show the validated form after the fix. The before image is a deterministic isolated reproduction: the deferred focus callback is held until description entry, then released mid-entry to show focus theft. It uses synthetic data and no live property.
- All captured UI data came from the E2E fixture/property. No live guest records, credentials, or session tokens were intentionally included in audit artifacts.

## C. Interaction inventory and named workflow evidence

The full inventory is available as [CSV](ui-interaction-inventory.csv) and [JSON](ui-interaction-inventory.json). Each row includes Page, Tab, Component, Action, Expected Behavior, Actual Behavior observed by the census, Result, and a screenshot link. Census rows are marked **NOT TESTED — inventoried only** where the individual action was not invoked. The row's actual behavior records rendered accessible name, disabled state, and keyboard reachability; it does not imply that the action worked.

Named E2E workflows passed for representative/high-value actions across these areas:

- **Admin operations:** guest request triage, sessions, guest links, stay notes, maps, Location directory, configuration save/publish/discard/restore, reports, webhooks, users/roles, and permissions.
- **Guest journeys:** home/explore/stay/requests/concierge navigation; hotel information; dining and recommendations; confirmed/cancelled service requests; Wi-Fi mock/validation flows; map and directions; privacy/consent; language/accessibility/help actions; and chat error/recovery paths.

## E. Security and accessibility findings

- Existing E2E checks for client-side API keys, stored XSS rendering, cross-property guest session boundaries, and selected UI/server permission checks passed in the final browser run.
- The control census found no missing accessible names, no enabled controls excluded from keyboard reachability, and no invalid ARIA composite entry points at the captured viewport.

- No live AI provider, email/SMS gateway, paid API call, or real guest notification was exercised. External integrations remain unverified by this audit.
